A retrieval-augmented generation service for text-based PDFs. It ingests PDFs, retrieves relevant passages with BM25, and asks an LLM to answer from those passages only, with citations the backend validates.

What I built

  • A two-stage RAG pipeline: validated PDF ingestion, page-bounded 100-word chunking and BM25 retrieval. The LLM answers only from the retrieved passages.
  • Citation validation: the model returns source labels as schema-constrained JSON validated with Pydantic. The backend rejects invented labels and takes filenames and page numbers from its own metadata, never from model output.
  • Honest abstention: the LLM is skipped when retrieval finds nothing, and answers with too little evidence are flagged as insufficient.
  • 6 REST endpoints with FastAPI, mapping provider timeouts, rate limits, refusals and malformed output to clear HTTP errors (400–504). All provider code sits behind a one-method LLMClient protocol.
  • 148 automated tests (unit, integration, API) that run with no API key or network, using a fake LLM client and a mock HTTP transport.
  • Diagnosed a rank_bm25 IDF bug that produced zero or negative scores on tiny corpora, and fixed it with a Lucene-style IDF subclass and a regression test.
